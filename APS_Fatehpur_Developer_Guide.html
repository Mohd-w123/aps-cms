APS Fatehpur — School Management System

Developer Guide & Prompt Strategy — CMS-Driven Dynamic Multi-School Website
Next.js · Node.js · MongoDB · Centralized Admin CMS

2-Day Build Plan  |  4 Schools  |  1 Admin CMS  |  English Only

Scope Clarification

What This Project IS
  • CMS-driven dynamic website — All content (text, images, pages) is managed from the Admin Panel.
  • English only — No multi-language, no i18n, no RTL. All 5 sites in English.
  • Fee structure = just a CMS page. Admin types fee info in the rich-text editor → renders on the website. No separate fee model.
  • Multi-tenant — One codebase, one DB, one admin panel manages all 5 school websites. Content scoped by schoolId.
  • Forms (Admission, Enquiry, Career Application) submit data to backend — admin views submissions.
What Is NOT Included
  • Multi-language / i18n (Urdu, Hindi)
  • RTL layout support
  • FeeStructure model / fee CRUD (fees = CMS page)
  • BusRoute model (bus routes = CMS page)
  • AcademicCalendar model (calendar = CMS page)
  • Translation files

Fees, bus routes, academic calendar, uniforms, curriculum, affiliation, RTE, career counseling — all rendered as CMS pages (rich text content managed from admin).

3. MongoDB Schema Design

Every collection has schoolId. All strings in English. No localized fields.

Collections (Simplified — No Fee/Calendar/Bus Models)
// ─── School ───
{
  _id, name, slug (unique), domain, subdomain,
  logo, favicon,
  theme: { primaryColor, secondaryColor, accentColor },
  contactInfo: { phone, email, address, mapEmbed },
  socialLinks: { facebook, instagram, youtube, twitter },
  stats: { students, teachers, years, awards },
  isActive, createdAt, updatedAt
}

// ─── User (Admin CMS users only) ───
{
  _id, schoolId (ref+index), name, email (unique),
  passwordHash, role: "superadmin" | "school_admin" | "editor",
  lastLogin, isActive, createdAt
}

// ─── Page (THE CORE CMS MODEL) ───
// Powers: about, fees, bus-routes, calendar, uniforms,
// curriculum, affiliation, rte, career-counseling, etc.
{
  _id, schoolId (index), slug (string),
  title (string), content (string — rich HTML from editor),
  featuredImage (string), seo: { metaTitle, metaDescription },
  isPublished (boolean), updatedBy (ref User),
  createdAt, updatedAt
}
// Compound unique index: { schoolId, slug }

// ─── Person (Director / Chairman / Principal) ───
{
  _id, schoolId, role: "director" | "chairman" | "principal",
  name, designation, bio (rich text string),
  photo, qualifications, order, isActive
}

// ─── News ───
{
  _id, schoolId, title, slug, content (rich HTML),
  category: "announcement" | "event" | "tour",
  featuredImage, images: [],
  isPublished, publishedAt, createdAt
}

// ─── Gallery ───
{
  _id, schoolId, type: "photo" | "video",
  title, url, thumbnailUrl, category,
  order, isPublished, createdAt
}

// ─── Topper ───
{
  _id, schoolId, studentName, photo, class,
  year, rank, percentage, examName,
  subjects: [{ name, marks }], isPublished, createdAt
}

// ─── AICU ───
{
  _id, schoolId, title, description (rich text),
  services: [{ name, description, icon }],
  images: [], schedule (string), isActive, createdAt
}

// ─── Admission (form submissions) ───
{
  _id, schoolId, studentName, parentName, phone, email,
  class, dob, gender, address, previousSchool,
  documents: [{ name, url }],
  status: "pending" | "reviewed" | "accepted" | "rejected",
  appliedAt, reviewedBy, reviewedAt
}

// ─── Enquiry (contact form submissions) ───
{
  _id, schoolId, name, email, phone,
  subject, message, status: "new" | "read" | "replied",
  createdAt
}

// ─── Career ───
{
  _id, schoolId, title, department, description,
  qualifications, experience, salary,
  isActive, deadline, createdAt
}

// ─── CareerApplication ───
{
  _id, careerId (ref), schoolId, name, email, phone,
  resume (url), coverLetter,
  status: "pending" | "shortlisted" | "rejected", appliedAt
}

// ─── Alumni ───
{
  _id, schoolId, name, batch, course,
  currentRole, company, photo, testimonial,
  isApproved, createdAt
}
Key insight: Fee structure, bus routes, academic calendar, uniforms, curriculum, affiliation, RTE, career counseling — ALL just Page documents with different slugs. Admin uses the rich-text editor to compose, frontend renders the HTML. No separate models needed.

DAY 1 Block 2 — Auth System (1.5 hrs)

Prompt D1-B2-P1 — Authentication Build admin authentication for the APS Fatehpur CMS. 1. POST /api/auth/login — email + password → validate → JWT (24h expiry, payload: userId, schoolId, role) → return { token, user } 2. GET /api/auth/me — protected, return current user profile 3. lib/auth.ts: - verifyToken(req) — extract JWT from "Authorization: Bearer ___" header or httpOnly cookie - withAuth(handler, allowedRoles?) — HOC wrapping API handlers, verifies JWT, optional role check - withSchoolScope(handler) — ensures user can only access their school's data (superadmin exempt) 4. Seed script (scripts/seed.ts): - Create 5 School documents matching config/schools.ts - Create 1 superadmin (admin@apsfatehpur.com) - Create 1 school_admin per school - Create default CMS Page documents for each school with placeholder content for these slugs: about, fees, bus-routes, calendar, uniforms, curriculum, affiliation, rte, career-counseling, facilities, tours, highlights, awards, infrastructure 5. Password: bcryptjs, 12 rounds. NEVER return passwordHash in responses. 6. Error format: { success: false, error: "message" }

DAY 1 Block 3 — All CRUD API Routes (2.5 hrs)

Prompt D1-B3-P1 — All API Routes Create all REST API routes using Next.js App Router (app/api/[resource]/route.ts). Response format: { success: true, data, pagination? }. Admin endpoints protected with withAuth. Public GETs filtered by schoolId from x-school-slug header. ROUTES: 1. /api/schools — GET (list active), GET by slug, PUT (superadmin: update settings/theme) 2. /api/users — GET (list by school), POST, PUT, DELETE (admin only) 3. /api/pages — GET by schoolId+slug (public: renders page content), POST, PUT, DELETE (admin) This is the CORE CMS endpoint. 4. /api/persons — GET by schoolId+role (public), POST/PUT/DELETE (admin) 5. /api/news — GET (paginated, filter by category), GET by slug, POST/PUT/DELETE (admin) 6. /api/gallery — GET (filter by type/category), POST with Cloudinary upload, PUT, DELETE (admin) 7. /api/toppers — GET (filter by year/class), POST/PUT/DELETE (admin) 8. /api/aicu — GET by schoolId, POST/PUT (admin) 9. /api/admissions — POST (public: submit), GET (admin: list by status), PUT (admin: update status) 10. /api/enquiries — POST (public: contact form), GET (admin: list), PUT (admin: mark read/replied) 11. /api/careers — GET (public: active), POST/PUT/DELETE (admin) POST /api/careers/apply — public: submit application with resume 12. /api/alumni — POST (public: submit for approval), GET (public: approved only), GET (admin: all), PUT (admin: approve/reject) 13. /api/upload — POST: file → Cloudinary → return { url, publicId } Pagination: page + limit query params (defaults: 1, 20). Input validation with Zod on all POST/PUT. Create a reusable apiHandler utility for DB connection, body parsing, error handling.

// components/school/CmsPage.tsx
export default async function CmsPage({ slug, schoolSlug }) {
  const res = await fetch(
    `${process.env.NEXT_PUBLIC_SITE_URL}/api/pages?slug=${slug}&school=${schoolSlug}`,
    { next: { revalidate: 3600 } }
  );
  const { data: page } = await res.json();
  if (!page) return <div>Content coming soon...</div>;

  return (
    <>
      <PageBanner title={page.title} image={page.featuredImage} />
      <div
        className="prose max-w-none"
        dangerouslySetInnerHTML={{ __html: sanitize(page.content) }}
      />
    </>
  );
}

// Usage — every CMS page is a one-liner:
// app/(public)/academy/fees/page.tsx
export default function FeesPage() {
  const school = getSchoolFromHeaders();
  return <CmsPage slug="fees" schoolSlug={school.slug} />;
}

7. Key Code Patterns

Multi-Tenant Middleware
// middleware.ts
const SCHOOL_MAP: Record<string, string> = {
  'apsfatehpur.com': 'apsfatehpur',
  'www.apsfatehpur.com': 'apsfatehpur',
  'apsgirls.apsfatehpur.com': 'apsgirls',
  'apsboys.apsfatehpur.com': 'apsboys',
  'madrasa.apsfatehpur.com': 'madrasa',
  'azadschool.in': 'azadschool',
  'www.azadschool.in': 'azadschool',
};

export function middleware(request: NextRequest) {
  const host = request.headers.get('host') || '';
  let slug = SCHOOL_MAP[host];
  if (!slug && host.includes('localhost')) {
    slug = request.nextUrl.searchParams.get('school') || 'apsfatehpur';
  }
  const res = NextResponse.next();
  res.headers.set('x-school-slug', slug || 'apsfatehpur');
  return res;
}
API Route Pattern
// app/api/news/route.ts
export async function GET(request: Request) {
  await connectDB();
  const schoolSlug = request.headers.get('x-school-slug');
  const { searchParams } = new URL(request.url);
  const page = parseInt(searchParams.get('page') || '1');
  const limit = parseInt(searchParams.get('limit') || '20');

  const filter: any = { schoolSlug, isPublished: true };
  const category = searchParams.get('category');
  if (category) filter.category = category;

  const [data, total] = await Promise.all([
    News.find(filter).sort({ publishedAt: -1 }).skip((page-1)*limit).limit(limit),
    News.countDocuments(filter),
  ]);

  return NextResponse.json({
    success: true, data,
    pagination: { page, limit, total, pages: Math.ceil(total/limit) },
  });
}

11. Speed Tips & Pitfalls

Speed Tips
  • CmsPage component is king: Build it once → 14+ pages become one-liners.
  • Seed script = your demo: Create default pages with realistic placeholder text.
  • Admin CRUD is repetitive: Build News admin first (DataTable + editor). Clone for Toppers, Careers, Alumni.
  • shadcn/ui saves hours: Don't build UI from scratch.
  • Deploy after Day 1: Push to Vercel early. Catch issues fast.
  • Get it working, then polish.
Common Pitfalls
  • Mongoose hot-reload: Use mongoose.models.X || mongoose.model(...)
  • localhost hostname: Always have ?school= fallback in middleware
  • react-quill SSR crash: Use dynamic(() => import('react-quill'), { ssr: false })
  • XSS via dangerouslySetInnerHTML: Always sanitize CMS HTML with DOMPurify
  • Cloudinary in next.config: Add to images.remotePatterns
  • MongoDB connection pool: Cache globally for serverless (lib/db.ts)
